# Deco Plotter

C#/.NET 10 backend + web dashboard for a TP-Link Deco mesh (tested protocol: local LuCI API, as used by
[ha-tplink-deco](https://github.com/amosyuen/ha-tplink-deco)).

It polls a Deco unit every few seconds, stores per-device and router-wide up/down rates in SQLite, and serves
a dashboard at **http://localhost:5180** (the thermostat backend on 5080 and Grafana on 3000 are untouched).

## Run

```powershell
cd src\DecoPlotter
dotnet user-secrets init
dotnet user-secrets set Deco:Password "<your Deco / TP-Link ID password>"
dotnet run
```

Settings live in `appsettings.json` (section `Deco`) and can be overridden by environment variables such as
`Deco__Host`, `Deco__Password`: `Host`, `Username` (default `admin`), `PollIntervalSeconds`, `RetentionHours`,
`SpeedUnitBytes`, `DatabasePath`, and `Urls` (listen address/port).

## API

| Endpoint | Description |
|---|---|
| `GET /api/status` | last poll time/error, current router rate |
| `GET /api/router/current` | current WAN up/down in bytes/s |
| `GET /api/router/history?minutes=60&maxPoints=600` | downsampled history + peak and total bytes |
| `GET /api/devices[?all=true]` | connected devices with current rates |
| `GET /api/devices/{mac}` | one device |
| `GET /api/devices/{mac}/history?minutes=60` | history for one device |
| `GET /metrics` | Prometheus metrics (see below) |
| `GET /api/usage?range=month` | per-device and router byte totals for `today`, `yesterday`, `week` (from Monday), `month`, `last7`, `last30`, or `custom` with `&from=yyyy-MM-dd&to=yyyy-MM-dd` |
| `GET /api/usage/{mac\|router}/daily?range=last30` | per-day totals for one device or the router |

## Prometheus / Grafana

Add a scrape job to `prometheus.yml` (use the host's address if Prometheus runs in Docker, e.g. `host.docker.internal:5180`):

```yaml
scrape_configs:
  - job_name: deco
    scrape_interval: 5s
    static_configs:
      - targets: ["localhost:5180"]
```

Gauges: `deco_up`, `deco_last_success_timestamp_seconds`, `deco_router_upload_bytes_per_second`,
`deco_router_download_bytes_per_second`, `deco_devices_online`, and per device
`deco_device_upload_bytes_per_second` / `deco_device_download_bytes_per_second` with labels `mac`, `name`, `ip`, `connection`.
In Grafana, multiply by 8 for bits/s (unit "bits/sec"). Offline devices disappear from the series.

## Notes

- Daily totals are stored per calendar day (server local time) in a `daily` table that is never purged, while raw samples
  are kept for `RetentionHours`. On first start after upgrading, the table is seeded from the existing raw samples.
- Client speeds include traffic between devices on your LAN (for example a backup to a NAS), not just internet traffic,
  so the "router" total can exceed your actual WAN usage.

- The Deco local API has no WAN counter. Router throughput is the **sum of the per-client speeds** (the same data the
  Deco app shows per client), so it excludes traffic generated by the Decos themselves.
- Deco reports `up_speed`/`down_speed` in KB/s; `SpeedUnitBytes` (default 1000) converts to bytes/s. Adjust to 1024 if
  your readings look consistently ~2.4% off versus a speed test.
- Logging in as the Deco `admin` account may sign you out of the mobile app (a Deco limitation); consider a secondary
  manager account.
- Passwords are never stored in the repo; use user-secrets or environment variables.
